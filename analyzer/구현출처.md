# 구현 출처와 실험 입력의 구별

이 폴더는 기존 연구 작업공간의 관계 인덱싱 구현을 **독립 실행 형태로 추출**했다. 실제 실험에서 사용한 원본 소스 묶음과 생성된 per-case 관계 DB는 이 공개 저장소에 포함하지 않는다. 공개 범위는 상위 [README](../README.md)와 [데이터 출처 안내](../DATA_SOURCES.md)를 참조한다.

핵심 알고리즘 파일 두 개는 원래 작업공간의 파일과 SHA-256이 같다.

| 파일 | SHA-256 |
| --- | --- |
| `src/relation_index/java.py` | `785c230e0e5bd74bcf7da93d539303ddb7937a15de996d440e20b4b852ab9d18` |
| `src/relation_index/indexer.py` | `d19221327d99958b91cd324b32bed946b7ab327a88f7e0f51d2557a762214594` |

`snapshot.py`는 독립 실행 저장 폴더와 전용 무시 파일 이름을 사용하도록 바꾸었다. `config.py`, `storage.py`, `queries.py`에서는 현재 B0/P1 비교에 쓰지 않는 기능과 테이블을 제거했고, `relation_index.py` 명령행 진입점을 추가했다. **따라서 이 프로그램을 지금 실행해 나온 새 ID를 예전 실험의 ID와 동일하다고 간주하지 않는다.** 분석 논문에서는 각 보관본의 실제 입력 해시·스냅샷 ID를 우선 인용한다.

기능 시험은 `tests/fixture`의 2개 Java 파일로 실시했다. 생성 결과: 파일 2, 기호 5, 호출 1, 관계 후보 4, 역할 단서 2. `context` 조회에서 `Controller.item` → `Service.find`의 `CALLS` 후보와 소스 줄을 함께 확인했다. 실제 호출 가능성이나 취약점 유무를 증명하는 시험은 아니다.

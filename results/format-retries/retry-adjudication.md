# CWE-Bench-Java P1 Flash Max 형식 오류 재실행 판정

## 범위와 판정 기준

- 대상: 기존 P1 응답이 제출 형식에 맞지 않았고, 기존 top-1 후보가 데이터셋 정답을 이미 맞힌 경우는 제외한 8건.
- 조건: DeepSeek-V4.1-Flash, reasoning effort `max`, P1, 사례당 새 리뷰 1회. 원래 프롬프트·소스 묶음·관계 자료를 유지했다. 원본 실험 결과는 수정하지 않았다.
- 형식 판정: 저장된 최종 `submit_review` 응답을 실행기에 전달된 스키마와 대조했다. 최상위 필드, 후보 수(최대 1), 후보 필수 필드와 자료형, 위치 형식, `rejected_leads`의 객체 구조를 검사했다.
- 정답 판정: 선택된 `candidates[0]`이 데이터셋이 지정한 취약점의 근본 원인과 일치할 때만 적중으로 셌다. CWE가 같거나 같은 파일·입력값을 언급했다는 이유만으로는 적중 처리하지 않았다. `rejected_leads`에 언급된 정답은 top-1 적중으로 세지 않았다.

## 집계

- LLM 응답 완료: **8/8**
- 제출 후보 수: 사례마다 1개, **8/8**
- 엄격한 응답 스키마 유효: **7/8 (87.5%)**
- 선택된 top-1 후보의 데이터셋 정답 적중: **0/8 (0%)**
- 유효 형식 응답만 분모로 한 적중: **0/7**
- 정답 취약점 단서가 비선택 `rejected_leads`에 나타난 사례: **1건 (case-149)**. top-1 적중률에는 포함하지 않았다.
- 같은 입력 매개변수/처리 경로를 언급했지만 지정된 취약점 종류와 결과를 특정하지 못한 사례: **1건 (case-082)**. 적중으로 세지 않았다.

이 8건은 형식 오류가 있었고 이전 top-1 후보가 정답인 사례를 제외해 골라낸 보충 표본이다. 전체 CWE-Bench-Java P1의 무작위 표본이 아니므로 이 비율을 전체 P1 성능으로 일반화하면 안 된다. 이 판정에서 미적중은 데이터셋 지정 정답을 top-1로 제출하지 못했다는 뜻이지, 제출한 다른 후보가 실제 취약점이 아니라고 확정한 뜻은 아니다. 별도 런타임 재현이나 독립 인간 검토는 수행하지 않았다.

이번 8건 재실행 원장 기록은 API 요청 **752건**, 합산 토큰 **129,450,628개**, 가격표로 계산한 추정 비용 **USD 1.0261**이다. 추정치는 실제 공급자 청구액이 아니다. 모델 요청 별칭은 `deepseek-flash`, 설정은 `max`다.

## 확인 근거와 출력 동결

모델의 최종 응답은 정답 자료를 대조하기 전에 저장되어 있었다. 각 `final_json`의 SHA-256과 바이트 수는 [retry-adjudication.json](retry-adjudication.json)에 기록했다. 데이터셋의 기존 판정 원장과 지정 CWE/CVE·수정 위치를 대조했다. 외부 확인은 애매한 두 사례의 취약점 유형을 구분하기 위해서만 사용했다.

- CVE-2011-2732: [NVD](https://nvd.nist.gov/vuln/detail/CVE-2011-2732)는 `spring-security-redirect`를 통한 CRLF 헤더 주입·응답 분할로 설명한다.
- CVE-2025-47771: [NVD](https://nvd.nist.gov/vuln/detail/CVE-2025-47771)는 `SparseMatrix`의 `read(InputStream)` 역직렬화 문제로 설명한다.

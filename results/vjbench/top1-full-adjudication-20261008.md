## 결과

## case-019 정정 판정 근거

새 P1 답변은 Jiffle 스크립트가 생성 Java 소스의 Javadoc 주석 안에 삽입되는 흐름과, `*/`가 이스케이프되지 않아 주석을 닫고 코드가 컴파일될 수 있는 원인을 지적했다. 이는 VJBench가 지정한 JAI-EXT Jiffle 코드 주입(CVE-2022-24816, CWE-94) 및 수정 커밋의 변경과 일치한다. 공식 저장소의 수정은 생성 주석에 포함되는 스크립트의 `*/`와 `/*`를 이스케이프한다. [공식 보안 권고](https://github.com/geosolutions-it/jai-ext/security/advisories/GHSA-v92f-jx6p-73rx), [지정 수정 커밋](https://github.com/geosolutions-it/jai-ext/commit/cb1d6565d38954676b0a366da4f965fef38da1cb)

이 판정은 답변과 지정 수정 커밋의 원인·수정 위치가 일치하는지를 본 정적 판정이다. 취약한 스크립트를 실행하거나 악용 가능성을 동적으로 재현한 것은 아니다. 새 실행은 DeepSeek V4.1 Flash `max`로 378.531초 동안 진행됐으며, 63회 API 요청과 144회 도구 호출을 기록했다. 사용량은 입력 7,019,866, 출력 63,675, 총 7,083,541 토큰이다. 가격 스냅샷 기반 추정액은 미화 0.084209달러이며 실제 청구 금액과 동일하다고 보장하지 않는다.

## 형식 및 판정 범위

- 최초 실행은 B0 42건, P1 42건이다. 최초 응답 네 건의 형식 오류에는 동일 조건의 별도 실행을 적용했다. 여기에 잘못된 입력을 바로잡은 case-019 P1 실행 한 건을 추가했다. 정정판은 사례·조건별 선택 결과 하나를 사용하고, 이전 P1 응답과 새 실행 원자료를 모두 보존한다. case-019 B0는 정정 입력으로 재실행하지 않았으므로 적중률 분모와 쌍대 비교에서 제외했다. 정답 메타데이터를 결과 확인 뒤 대조한 사례가 있어 사후 판정의 선택 편향 가능성은 남아 있다.
- “미적중”은 지정된 VJBench 타깃과 일치하지 않았다는 뜻이다. 해당 후보가 다른 실제 취약점인지 또는 안전한 코드인지를 판정한 것이 아니다. 후보를 실행하거나 수정 전후 동적 테스트를 수행하지 않았다.
- 이 대조는 한 번의 실행에 대한 소스·수정 커밋 기반 판정이다. 독립된 두 명의 인간 평가자 검토가 아니다.
- CVE-2021-43859의 공식 설명은 재귀 구조가 컬렉션·맵의 해시 계산 비용을 급증시켜 서비스 거부를 일으킬 수 있다고 설명한다. case-032 B0는 그 원인을 구체적으로 짚었고, P1의 일반적인 깊이·크기 제한 주장은 지정 원인과 구분했다. [GitHub Advisory](https://github.com/advisories/GHSA-rmr5-cpv2-vgjf)
- case-040의 공식 CVE 설명은 LemMinX의 안전하지 않은 리다이렉트로 로컬 민감 정보가 노출될 수 있는 문제다. 따라서 두 조건의 XSD 엔터티 후보는 같은 제품·XML 영역에 있어도 지정 원인 적중으로 보지 않았다. [NVD CVE-2022-0672](https://nvd.nist.gov/vuln/detail/CVE-2022-0672)
- case-006 B0는 이 대조에서 CVE-2018-18893의 지정 타깃과 달라 미적중이다. 다만 Jinjava의 ForTag 제한 우회에 관한 별도 보안 권고가 나중에 게시되어 있으므로, 미적중을 그 후보의 허위 판정으로 해석하지 않는다. 별도 취약점 확인·재현은 이 대조의 범위가 아니다. [Jinjava GitHub Advisory](https://github.com/HubSpot/jinjava/security/advisories/GHSA-gjx9-j8f8-7j74)
- case-026은 로컬 `VJBench_data.json`의 저장소/CVE 메타데이터가 CSV와 다르다. 사전 고정 프로토콜에 따라 CSV의 저장소, CVE, 수정 커밋을 판정 기준으로 사용했다.

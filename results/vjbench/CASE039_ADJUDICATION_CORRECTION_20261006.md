# VJBench case-039 판정 정정 기록

작성일: 2026-10-06

적용 대상: DeepSeek V4.1 Flash Max, VJBench Top-1 B0/P1

## 정정 내용

초기 판정에서는 `case-039 / Lemminx-2`를 평가에서 제외했다. CSV에 연결된 `b46cb1f283c70b85c22221b30a4aff62be495237`는 CVE-2022-0671 수정이 아니라 DTD SYSTEM 식별자 처리 문제를 다루는 커밋이다. 원자료의 수정 커밋 연결은 잘못됐지만, 이것만으로 해당 CVE가 분석 입력에 존재하지 않는다고 볼 수는 없다.

공식 CVE 설명은 LemMinX 0.19.0 이전의 스키마 다운로드에서 발생할 수 있는 blind SSRF 또는 대용량 파일 DoS를 명시한다. 이 실험의 소스는 0.18.5-SNAPSHOT이며 보안 수정 PR #1174가 병합되기 전 버전이다. PR #1174는 리소스 다운로드 프로토콜과 안전하지 않은 리디렉션을 제한했다. 따라서 case-039는 타깃이 확인 가능한 사례로 복원했다. [NVD CVE-2022-0671](https://nvd.nist.gov/vuln/detail/CVE-2022-0671), [Eclipse LemMinX PR #1174](https://github.com/eclipse-lemminx/lemminx/pull/1174), [잘못 연결된 원래 커밋 b46cb1f](https://github.com/eclipse-lemminx/lemminx/commit/b46cb1f283c70b85c22221b30a4aff62be495237).

P1 원본 응답은 공격자가 조절하는 XSD/DTD 외부 참조가 리소스 해석기를 거쳐 외부 요청을 일으키는 경로와 SSRF 영향을 설명해 적중으로 판정했다. B0 원본은 필수 형식 오류여서 점수화하지 않았고, 별도 형식 보충 응답이 같은 SSRF 경로를 설명해 형식 보정 분석의 적중으로 반영했다. 큰 응답에 의한 DoS나 수정 PR의 모든 프로토콜·리디렉션 세부를 후보가 독립적으로 짚은 것은 아니다. 코드 실행을 통한 동적 재현도 하지 않았다.

정답 메타데이터 연결과 답변 판정은 기존 모델 출력을 확인한 뒤 수정됐다. 그러므로 아래는 사전 등록된 독립 평가가 아니라 사후 정정 결과다.

형식 보정 분석의 사례별 쌍대 결과는 양쪽 적중 15건, B0만 적중 4건, P1만 적중 4건, 양쪽 미적중 19건이다. 순 적중 차이는 0이며, 불일치 쌍은 4 대 4다.

따라서 기존 보고서의 “41개 판정, 18/41씩”은 현재 최종 형식 보정 분석을 나타내지 않는다. case-039를 포함한 최종 분석 분모는 42이고, 적중은 B0와 P1 모두 19건이다. 원본 응답만 별도로 제시할 때는 위의 형식 유효 분모를 사용한다.

## 기록 보존

기존 2026-10-05 동결 스냅샷은 수정하지 않았고, 그 안의 case-039 보류 판정은 당시 기록으로 보존한다. 현재 판정은 버전이 지정된 [기계 판독용 정정 기록](case-039-adjudication-correction-20261006.json), [전체 판정 보고서](top1-full-adjudication-20261006.md), [행 단위 CSV](top1-full-adjudication-20261006.csv)에 기록했다. 원본 실행 결과와 원장도 덮어쓰지 않았다.

정정 반영으로 전체 데이터셋 산술 참고치는 631개 평가 행, B0 192건(30.43%), P1 209건(33.12%)으로 바뀐다. CWE-Bench-Java를 제외한 선택 집계는 419개 행, B0 95건(22.67%), P1 117건(27.92%)이다. 이 합계들은 중복·비독립 사례를 포함하므로 단일 성능 추정치로 해석하지 않는다.

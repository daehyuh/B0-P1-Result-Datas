# Vul4J 79사례 B0·P1 정답 대조 및 전체 통계

작성일: 2026-10-02

## 요약

기존 75사례 strict-reaudit-v2 판정을 보존한 채, 보완된 VUL4J-57·69·70·71의 24개 실행(4사례 × B0/P1 × 3 프로파일) 후보 16건을 지정된 Vul4J 패치·테스트 정답과 대조했다. 새 보완분에서 정답과 일치한 실행은 **1/24**이며, VUL4J-69 Flash High P1 한 건이다. 나머지 **23/24는 데이터셋 지정 정답을 제출하지 못한 실행**이다.

| 보완 사례 | B0 적중 | P1 적중 | 판정 요점 |
|---|---:|---:|---|
| VUL4J-57 | 0/6 | 0/6 | SECURITY-433 권한검사 누락을 찾지 못함. CSV의 CVE 번호 오류는 본문에 명시 |
| VUL4J-69 | 0/6 | 1/6 | Flash High P1이 ResourceServlet의 미정규화 요청 경로를 정확히 지적 |
| VUL4J-70 | 0/6 | 0/6 | HttpRange 다중/중첩 Range 요청 DoS 정답을 찾지 못함 |
| VUL4J-71 | 0/6 | 0/6 | multipart 경계값 예측 가능성/오염 정답을 찾지 못함 |

VUL4J-57의 used CSV는 `CVE-2018-1000089`라고 적었으나, 해당 번호는 NVD상 Django Anymail 취약점이다. 이 Vul4J 사례의 지정 수정 커밋과 테스트는 Jenkins SECURITY-433 / **CVE-2017-1000089**, 즉 downstream job 실행 전에 `Item.BUILD` 권한을 확인하지 않는 문제를 가리킨다. 따라서 주 집계는 명확한 패치·테스트 표적을 기준으로 포함하되, 민감도 분석에서 57번을 제외한 값도 제공한다.

## 후보 단위 판정과 해석 제한

전체 474회에서 후보 제출은 815건이다. 기존 strict-reaudit-v2 판정에 새 후보 16건의 결과를 더하면 후보 행 단위로 MATCH 68, PARTIAL 44, EQUIVALENT_VARIANT 3, NO_TARGET_MATCH 691, GROUND_TRUTH_CONFLICT 9건이다. 후보 행 분류는 정답 발견 사례 수와 다르다. 특히 NO_TARGET_MATCH 691건을 모두 입증된 보안 오탐이라고 부를 수는 없다. 본 사용자의 이진 규칙으로 세면, 정답 판정 가능한 실행 468건 중 404건은 지정 정답 미탐/불일치다.

- 새 16개 제출 후보: MATCH 1, PARTIAL 1, NO_TARGET_MATCH 14.
- 새 24회 실행: 지정 정답 일치 1회, 정답 미발견 23회. 후보를 내지 않은 실행도 미발견에 포함한다.
- CVE/패치·테스트 표적에 기반한 사후 검토이며, 동적 PoV 재현은 수행하지 않았다.
- 기존 75건 판정은 이전 strict-reaudit-v2를 그대로 승계했고, 추가 4건의 16개 제출만 새로 검토했다.
- 보완 입력은 snapshot-v7; 과거·보완 프로파일 간 mining loop 버전 차이가 있으며 `merge-manifest.json`에 세부가 남아 있다. B0/P1 쌍 안에서는 동일 버전의 실행을 맞췄지만, 모델 프로파일 간 비교는 실행 루프까지 완전히 동일하지 않다.
- VUL4J-57의 CSV CVE 오기 사례를 제외해도 적중 수는 같고 분모는 77이 된다. 각 모델의 B0/P1 비율은 evaluation-summary-79.json의 민감도 분석 객체에 기록했다.
- VUL4J-1의 판정 충돌 6회는 분모에서 제외했지만 원시 실행·비용은 보존했다.

## 새 네 사례의 정답 판정 근거

- **57**: Jenkins 수정 커밋은 `BuildTriggerStepExecution.start`에 `item.checkPermission(Item.BUILD)`를 추가하고, failing test `SECURITY-433`은 권한 없는 downstream build trigger를 검증한다. 공식 권고는 CVE-2017-1000089로 명시한다.
- **69**: ResourceServlet 수정은 `StringUtils.cleanPath(url)` 후 allowed-resource 검사 및 include를 수행한다. Flash High P1 후보 2가 이 raw resource path 흐름을 식별했다.
- **70**: 공식 설명은 높은 수의 Range 또는 넓게 겹치는 Range가 서비스 거부를 유발할 수 있다고 명시한다. 제출 후보는 이 경로를 지적하지 않았다.
- **71**: 공식 설명은 multipart boundary를 추측해 content pollution을 일으키는 공격을 설명한다. 수정 커밋은 MimeTypeUtils boundary generation에 SecureRandom을 사용한다. 제출 후보는 이 원인을 지적하지 않았다.

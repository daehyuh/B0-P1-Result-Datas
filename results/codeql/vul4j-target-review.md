# Vul4J CodeQL 79사례 지정 취약점 대조

현재 연구 집계에서는 완료된 실행에서 지정 취약점 적중 근거가 확인되지 않으면 미적중으로 산정한다. `VUL4J-1`의 CVE 정답을 재확인한 후 이 사례와 기존에 판단을 유보했던 `VUL4J-29`를 미적중에 포함했다. `VUL4J-1`의 재판정 근거는 `VUL4J-1-CodeQL-CVE-재판정-20261008.md`에 기록했다.

## 요약

CodeQL 분석은 79개 사례 모두 정상 완료됐다. SARIF 경고 12,385건을 사례별 정답과 대조한 결과, 지정 취약점과 직접 일치하는 근거를 확인한 사례는 **11/79건(13.92%)**, 확인하지 못한 사례는 **68/79건(86.08%)**이다. `VUL4J-1`과 `VUL4J-29`에서도 경고는 나왔지만 각 사례의 지정 원인을 탐지했다는 근거가 부족하므로 미적중으로 산정했다.

| 항목 | 결과 |
| --- | ---: |
| CodeQL 분석 완료 | 79/79 사례 |
| SARIF 경고 전체 | 12,385건 |
| 판정 사례 | 79건 |
| 지정 취약점과 직접 일치 | **11/79 (13.92%)** |
| 지정 취약점 미적중 | **68/79 (86.08%)** |
| 경고가 1건 이상 나온 사례 | 73/79 |
| 경고가 0건인 사례 | 6/79 |

경고가 1건 이상 나왔다는 사실은 해당 사례의 지정 취약점을 찾았다는 뜻이 아니다. 경고 12,385건을 취약점 12,385건으로 해석하지 않는다. 또한 지정 취약점과 일치하지 않은 경고를 전부 오탐이라고 단정하지 않는다. 이 자료만으로는 경고 각각의 실제 취약성 여부를 모두 검증하지 않았다.

## 판정 기준

SARIF의 규칙 종류, 주요 코드 위치, 데이터 흐름 위치를 Vul4J의 사례별 취약점 설명 및 참조 수정 파일과 대조했다. 경고가 같은 프로젝트나 파일에 있다는 이유만으로 적중 처리하지 않았다. 예를 들어 같은 파일에서 보고된 다른 형변환·로깅·암호 사용 경고는 지정된 취약점의 원인과 일치하지 않으면 적중에서 제외했다.

이번 대조는 결과 정리를 위한 코드·경고 위치 검토이며, 독립된 두 명의 검토자가 수행한 블라인드 판정은 아니다. 적중 근거가 부족한 사례를 미적중으로 산정했으며, 이는 해당 경고 자체가 모두 오탐이라는 판정과 다르다.

## 미적중 사례

`VUL4J-29`에서는 CodeQL이 쿠키 입력에서 OGNL 값 설정까지의 흐름을 경고했다. 다만 정답 취약점은 쿠키 경로에서 특정 내부 컨텍스트 패턴을 전역 제외 목록에 넣지 않은 문제다. 경고가 이 구체적인 필터 누락을 식별했다는 근거가 부족하므로 미적중으로 산정한다.

`VUL4J-1`은 데이터셋에 연결된 수정 패치와 CVE가 서로 다른 문제를 가리키지만, CVE 설명을 정답으로 정해 79건 비교에 포함했다. CodeQL의 일반 역직렬화 경고는 지정된 AutoType 원인을 특정하지 않아 미적중으로 산정한다. 판단 근거는 별도 재판정 문서에 있다.

미적중 68건: VUL4J-1, 3, 7–25, 27–29, 31–32, 34–42, 44–60, 62–64, 66–78.

경고가 전혀 나오지 않은 사례는 **VUL4J-25, 51, 52, 57, 60, 76**이다. 나머지 미적중 사례에서는 경고가 있었더라도 지정 취약점과 직접 일치하는 근거를 확인하지 못했다.

## Flash Max P1과의 사례 단위 비교

같은 79개 사례에서 Flash Max P1의 지정 취약점 적중은 11/79(13.92%)였다. 이는 CodeQL 경고 건수와 직접 비교한 것이 아니라, 각 사례의 지정 취약점을 맞혔는지를 비교한 값이다.

| 결과 | 사례 수 |
| --- | ---: |
| CodeQL 직접 일치 | 11/79 (13.92%) |
| Flash Max P1 적중 | 11/79 (13.92%) |
| 두 조건 모두 적중 | 2건: VUL4J-61, VUL4J-79 |
| CodeQL만 적중 | 9건 |
| Flash Max P1만 적중 | 9건 |
| 둘 다 적중하지 않음(엄격 판정) | 59건 |

따라서 이번 결과에서 관찰되는 것은 CodeQL이 P1과 다른 사례들을 찾아냈다는 점이다. 이 한 번의 실행만으로 P1이 CodeQL보다 우수하거나 열등하다고 결론내릴 수는 없다. 특히 두 방식은 분석 절차와 출력 형식이 다르고, CodeQL 경고의 정밀도·실행 비용을 별도로 평가하지 않았다.

## 실행 조건과 한계

- CodeQL CLI 2.23.2, Java query pack 1.8.1, `java-security-extended.qls`를 사용했다.
- 데이터베이스 생성 설정은 `build-mode: none`이었고, 각 사례의 취약점 수정 전 B0 소스 묶음을 분석했다.
- 전체 79건에서 SARIF 경고 12,385건이 나왔다.
- 이 경고 수는 취약점 수나 오탐 수가 아니다. 미적중 경고가 다른 실제 취약점인지, 안전한 코드에 대한 오탐인지 전부 확인하지 않았다.
- VUL4J-1은 CVE 설명이 가리키는 다형성 역직렬화 문제와 연결된 수정 패치·회귀 테스트의 일반 배열 형식 문제가 일치하지 않는다. 비교 정답은 CVE 설명으로 고정했고 CodeQL은 그 지정 원인 미적중으로 산정했다.
- 토큰 사용량은 적용되지 않는다. 여기서 제시한 통계는 실행 완료 수, SARIF 경고 수, 지정 취약점의 사례 단위 일치 수다.
